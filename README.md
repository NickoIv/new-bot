# New Bot

New Bot — Telegram-бот для самостоятельных путешественников: новости и погода, визы, рейсы,
отели, достопримечательности, кафе, курс валют и практическая информация по
**Вьетнаму, Индонезии (Бали), Сингапуру, Египту и Хайнаню (Китай)**.

Весь интерфейс — reply-кнопки внизу экрана, всё содержимое на русском
(новости переводятся автоматически).

---

## Возможности

| Раздел | Что внутри |

| 🌴 Все новости | свежий дайджест по всем направлениям, переведённый на русский |

| 🏛 Достопримечательности / ☕ Кафе | кураторские подборки с описаниями + добор из OpenStreetMap, сгруппировано по категориям |

## Имя этого экземпляра

В сообщениях бот отображается как **New Bot**. Имя и username в профиле
Telegram задаются отдельно у [@BotFather](https://t.me/BotFather): для нового
экземпляра создай **отдельного** бота, задай ему имя `New Bot` через `/setname`
и используй выданный им новый `BOT_TOKEN`. Нельзя использовать тот же токен,
что у исходного бота: это был бы один и тот же Telegram-бот.

GitHub-репозиторий предназначен для имени `new-bot` (при конфликте —
`new-bot-2`).

## Структура

```

```

## Запуск локально

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env        # и вписать BOT_TOKEN
export BOT_TOKEN="123456:ABC..."    # Windows PowerShell: $env:BOT_TOKEN="123456:ABC..."
python bot.py
```

Без переменной `WEBHOOK_MODE` бот работает через long polling — вебхук и
публичный адрес не нужны. Дайджест в этом режиме рассылает встроенный JobQueue.

## Переменные окружения

| Переменная | Обязательна | Зачем |
|---|---|---|
| `BOT_TOKEN` | да | токен от [@BotFather](https://t.me/BotFather) |
| `WEBHOOK_MODE` | нет | `1` — поднять HTTP-сервер вместо polling |
| `PORT` | нет | порт HTTP-сервера, по умолчанию `8080` |
| `DAILY_CRON_SECRET` | **на публичном хостинге — да** | защита `POST /cron/daily` (заголовок `X-Cron-Secret`) |
| `WEBHOOK_PATH_SECRET` | **в webhook-режиме — да** | случайный путь webhook; токен бота в URL не используется |
| `TELEGRAM_WEBHOOK_SECRET` | **в webhook-режиме — да** | Telegram передаёт его в проверяемом заголовке webhook |
| `UPSTASH_REDIS_REST_URL` / `..._TOKEN` | нет | внешнее хранилище подписок; без них данные лежат в файле и теряются при перезапуске контейнера |
| `UPSTASH_REDIS_KEY` | нет | ключ данных в Redis; по умолчанию `new_bot_data`, чтобы не смешать этот экземпляр с исходным |
| `DATA_FILE` | нет | путь к файлу данных (по умолчанию — рядом с `bot.py`) |

Полное описание — в `.env.example`.

## Деплой (webhook-режим, например Render)

1. Собери и запусти сервис (Docker или `web: python bot.py`).
2. Задай переменные `BOT_TOKEN` и `DAILY_CRON_SECRET`.
3. Сгенерируй две разные секретные строки для `WEBHOOK_PATH_SECRET` и
   `TELEGRAM_WEBHOOK_SECRET`, затем пропиши webhook. В URL передаётся только
   путь-секрет, а не токен бота:
   ```
   curl -F "url=https://<домен>/webhook/<WEBHOOK_PATH_SECRET>" \\
        -F "secret_token=<TELEGRAM_WEBHOOK_SECRET>" \\
        -F "drop_pending_updates=true" \\
        "https://api.telegram.org/bot<ТОКЕН>/setWebhook"
   ```
4. Ежедневную рассылку дёргает внешний крон (например, cron-job.org):
   ```
   POST https://<домен>/cron/daily
   X-Cron-Secret: <значение DAILY_CRON_SECRET>
   ```
   Раз в сутки, в 05:00 UTC (10:00 Алматы). Эндпоинт отвечает сразу и делает
   рассылку в фоне, поэтому таймаут крон-сервиса ему не мешает.
5. Проверка живости: `GET /` или `GET /health` → `ok`.

### Бесплатный запуск на Render

В репозитории есть `render.yaml`: при создании Web Service из репозитория он
предложит режим Docker, `WEBHOOK_MODE=1`, health-check `/health` и полный
список секретов без их значений. Задай реальные значения только в панели
Render, не в GitHub и не в файле `render.yaml`.

Для бесплатного инстанса обязательно подключи Upstash Redis через
`UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`: локальный файл
контейнера пропадает после сна, перезапуска или нового деплоя. Free-инстанс
Render может заснуть после простоя и просыпается по входящему запросу; это
подходит для хобби-проекта и теста, но не является гарантированным 24/7 SLA.
После создания сервиса проверь `/health`, настрой webhook по инструкции выше
и сделай тестовую команду `/start` в Telegram.

## Безопасность токенов

В опубликованный код не добавляются реальные значения. Для нового экземпляра
создай отдельный токен у [@BotFather](https://t.me/BotFather); настоящее
значение хранится только в локальном `.env` или в секретах хостинга. Файлы
`.env`, ключи и локальные данные исключены через `.gitignore` и Docker ignore.
Перед каждым push запускай самопроверку ниже и не публикуй токены в issue,
скриншотах или истории коммитов.

## Самопроверка

```bash
python selfcheck.py
```

Работает полностью офлайн и без токена. Проверяет три вещи:

1. **целостность данных** — у каждой страны и города есть все разделы,
   кураторские подборки и маршруты ссылаются на существующие города, подписи
   кнопок не конфликтуют;
2. **HTML-безопасность** — ни один текст, уходящий с `parse_mode="HTML"`, не
   содержит неподдерживаемых или незакрытых тегов (отдельно прогоняется
   «враждебный» заголовок новости с `<script>` и амперсандами);
3. **прогон интерфейса** — весь бот кликается фейковым Telegram'ом: все страны,
   все города, все кнопки. Ловится молчание бота и исключения в обработчиках.

Код выхода `0` — всё чисто.

## Известные ограничения

* **Состояние навигации хранится в памяти процесса.** После перезапуска
  (на бесплатном Render это происходит регулярно) бот не помнит, в каком экране
  был пользователь. Reply-кнопки при этом остаются в клиенте — такие нажатия
  теперь не игнорируются, а вежливо предлагают выбрать раздел заново, но при
  желании это можно вынести в то же хранилище, что и подписки.
* **Публичные зеркала Overpass API периодически недоступны** — список
  достопримечательностей и кафе тогда состоит только из кураторских подборок
  (они показываются всегда).
* **Кураторские тексты (визы, цены, телефоны) — статические.** Они не
  обновляются сами: раз в сезон их стоит сверять с официальными источниками.
